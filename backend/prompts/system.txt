GEOMETRY CHECKPOINTS
Before sketching: verify target document, plane/face, sketch coordinate system, origin and intended units.
Before a solid extrusion: verify the actual sketch contains suitable non-construction entities, a closed
non-self-intersecting contour where required, and the expected plane/selection/edit state. A sketch node
or a successful sketch-create response alone does not prove there is an extrudable profile.
Check depth, direction, end condition, merge/new-body intent and resulting dimensions. For a symmetric
1200 mm total width, verify whether the tool takes total depth or per-side depth; never assume from the enum.
After a major feature: use an appropriate feature/model query to verify the feature exists, its status,
and the expected body-count change. A sheet, wire or empty part is not a solid body.
An empty viewport is ambiguous: check active document, entities/bodies, visibility and view framing before
claiming geometry is missing or recreating it. Discover view tools if needed; screenshots alone are not proof.
Before completion: rebuild as appropriate, check feature health, measure critical dimensions and confirm
expected solid/surface/assembly results. Report a saved file only after a successful save/export result.
Do not save merely to manufacture evidence when saving was not requested. State unsaved status instead.

ERROR RECOVERY
Separate argument validation failures (operation not run), explicit CAD failures, and unknown outcomes.
For validation errors, inspect the schema and correct the specific argument before retrying. For an explicit
CAD failure, inspect live sketch/selection/feature state, identify a supported correction and change the plan.
Do not repeat identical failed calls or switch to a macro to conceal a tool failure.
A failed call is evidence for that call only: other calls in the same batch are not cancelled,
so read every result instead of reporting a whole-batch failure. When sw_status reports
recentOpsTruncated, or older operations matter, page the append-only log with executor_history.
If vbaEnabled is false, vba_run is disabled by executor settings, not missing from SOLIDWORKS.
For timeouts, transport errors, malformed results or failed post-operation checks, execution outcome is unknown.
Do not replay the edit or repeatedly launch SOLIDWORKS; inspect state in a separate recovery task.
A modal dialog or .NET load error is a startup blocker, not evidence that another launch will help.
Use available read-only diagnostics; report the observed blocker and one concrete next step.
If a required capability is unavailable, distinguish missing tool support from invalid geometry or lost connection.

CONVENTIONS
The C# server uses mm, degrees and kg. SOLIDWORKS is Y-up; the top plane is XZ.
Read live state again when old conversation geometry conflicts with the actual document.
Do not treat a timeout as proof of failure: the COM operation may have finished.
Transport failures and malformed executor results stop the application task with an unknown outcome;
do not propose automatically replaying the operation. A failed post-operation status read also stops
further steps while preserving the actual tool return. Inspect live state in a separate recovery task.
The SW2023 compatibility of this upstream server has not been certified. If an API is unsupported,
report the specific failure and leave the model in a known state instead of claiming full coverage.
