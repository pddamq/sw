# 工程闭环（0.9.0 源码功能）

工程闭环是可选的任务执行模式。它将需求确认、版本化核验清单、SolidWorks 现场取数、确定性检查和有限自动修复接入现有任务循环。当前属于首版基础能力，不是完整制造规则引擎。

## 使用

1. 在输入框工具栏勾选“工程闭环”，描述目标文档、工艺、材料、功能、尺寸和验收要求。开关默认关闭；入队消息保留入队时的选择。
2. 模型通过 `engineering_rules` 加载相应工艺清单，使用知识库工具查阅项目或工厂资料，然后调用 `engineering_plan` 提交需求确认卡。
3. 核对目标标题、全部需求、预期值、依据及检查方式。选择确认且没有附带修改文字后，需求及规则包冻结。选择补充或填写修改意见时，保持未确认并重新规划。
4. 涉及总装与子零件时，模型先单独调用 `engineering_scope_extend`，为每个子零件或子装配登记精确标题、类型、工艺、材料和完整要求。逐张确认后，本批范围统一生效；既有约束保持不变。然后调用原有 CAD 工具建模，仍保留原操作审批。
5. `engineering_check` 和任务收尾的强制检查读取真实 CAD 返回，生成逐项报告。失败项反馈给主模型修复并重检；未知项转为待人工核验。
6. 在任务的“检查点与验证证据”查看报告，导出 JSON 可获得最新报告、历次工程报告及工具检查点。

恢复核对任务继续只读，不因勾选工程闭环而恢复修改。任务中插话会使旧报告失效，要求重新确认需求。

项目支持一个主文档和显式确认的子零件/子装配/工程图。已打开文档在确认前后核对句柄、规范化路径、类型和 SOLIDWORKS 进程身份；执行器连接所有者也保持绑定。同名文件不自动继承确认，身份变化后需核对现场并新建任务重新确认。

现有文件应先打开再开始工程任务；新建且由执行器拥有的未保存文档，用 `doc_save mode=as` 首次保存，文件基本名须与已确认名称一致。原保存审批保持，审批后再次核对目标；保存后读取真实路径、标题及句柄，核对成功才更新现场绑定，不修改冻结需求或范围摘要。已有文件用 `inPlace`，`copy` 只导出独立副本，不把副本当成原活动文档。仍拦截已有文件重命名式 Save As、任务内打开其他文件和任意 VBA 宏。

工程模式暂时拦截 `asm_structure kind=form` 与 `asm_pattern oppositeHand=true`，因为当前执行器没有提供可在创建前绑定的完整派生文档身份。使用显式确认、`doc_new`、同名首次保存及 `asm_insert` 组织项目；普通实例阵列、普通实例镜像及非工程任务原有能力保持。

工程图支持 `document_type=drawing` 的确认、创建、结构化编辑和保存；读取 `model_info` 及 `drw_info`，不对图纸调用零件 `model_check`。图纸健康、视图/标注完整性、模型引用和交付一致性尚无完整判定器，保持 UNKNOWN；零件实体与材料基线在图纸上标记 NOT_APPLICABLE。

固定只读清单补齐草图、组件/配合、实体/面/边/顶点、材料/属性/方程/配置及图纸概览等查询，不使报告失效，也不消耗修改预算。外部执行器任意声明 readOnlyHint 不会自动获得该待遇。收尾执行器断连、状态工具缺失或复核异常会使旧通过报告失效，任务不会按工程复核完成结束。

## 总装与子零件范围修复（后续源码更新）

此前只确认总装标题时，正常编辑独立底板会被单文档检查拦截。现在模型可以调用 `engineering_scope_extend` 追加文档，而不是重建同名零件或重连。追加接口仅增加文档，不覆盖主文档或已有子文档的尺寸、材料、要求及规则包。

- 每次追加 1 至 4 个文档，每个都需要完整需求及 `document_type=part|assembly|drawing`；一个任务包含主文档在内最多 16 个文档、最多 8 次追加提案。
- 每个子文档使用独立确认卡。先校验整批输入，全部确认后才提交范围；任一取消、跳过、附带修改意见或等待中断，整批均不生效。
- 追加范围不批准 CAD 修改。修改仍须通过已有工具审批和所有权检查；范围外文档继续拦截。标题、句柄及路径均先在现场唯一定位，再检查其属于确认范围；省略 `doc` 时也只接受唯一的已确认默认目标。
- 已打开的同名文档应复用，`doc_new` 不重建它；新文档的名称和类型必须符合已确认条目。
- 主文档和全部已确认子文档逐个取数、逐个判定。报告逐项带文档名，缺陷 ID 按文档隔离，材料要求分别核对子零件；空总装明确标为失败。
- 子文档缺失、未打开、身份不唯一或证据不足时保持 UNKNOWN。装配的健康检查不会代替子零件几何、材料和尺寸检查；确认范围也不证明零件已装入总装，装配关系及路径仍需独立核验。
- 任一文档修改或范围追加后，旧项目报告失效；取数期间任何文档状态变化会使本轮所有判定失效，重新检查整个项目。
- 用户插话后重新确认主计划，已确认子文档及其约束仍保留。新增文档不重置检查/修复预算；在范围不变时沿用原无进展停止条件。

对于已经停止的旧任务，升级后新建续作任务，保留原需求并重新确认，先读取 `doc_list`，把已存在底板的实际标题追加确认，再继续编辑。任务历史与旧证据保留，不自动重放旧操作；只读恢复核对任务仍不执行修改。

## 规则与证据

- `backend/engineering_rules.py` 提供版本为 `1.1.0` 的内部核验清单，覆盖概念、机加工、钣金、注塑、铸造、焊接、增材、装配及其他工艺。
- 清单记录标识、版本、适用工艺、来源性质、证据要求和已支持的检查器。自动附加到计划，即使模型没有主动加载，也不会遗漏该工艺的内置待核验项。
- 内部清单不是行业标准，不含猜测的制造数值。知识库检索内容不会自动成为可执行代码或已认证标准；模型填写的来源说明也不等于已独立核实的引用。
- 需求与规则包分别计算 SHA256，并在检查/修改入口验证未变化。报告按任务追加到 SQLite，保留取数时间、前后状态、原始观测、失败原因及修复次数。

## 首版自动检查范围

已实现：目标文档身份、模型健康返回、零件实体几何有效性、指定实体数量、CAD 材料名称精确匹配，以及命名模型尺寸范围和标注公差包络检查。

基线读取 `sw_status`、`model_info`、`model_review`、`model_check`。检查前后文档、配置、句柄、修改戳及连接状态必须一致。缺少执行器工具、旧版本没有修改戳/完整性字段、返回警告、截断或取数期间变化，都保持 UNKNOWN。健康检查中的警告也不会作为无问题证据。

尚无自动判定适配器：最终实体距离、形位公差与公差链、孔边距/折弯半径的几何识别、刀具可达性、完整制造工艺、强度、装配路径及导出一致性。这些要求保留 UNKNOWN，不能因模型自述“完成”变为 PASS。装配的零件几何检查标为 NOT_APPLICABLE，并保留独立的装配待核验项。

报告状态：
- PASS：该检查器在本次快照中通过。
- FAIL：有确定证据违反已确认要求。
- UNKNOWN：证据或适配器缺失，需补资料或人工核验。
- NOT_APPLICABLE：该检查在此文档类型不适用，并记录原因。

`checks_passed` 仅表示已实现的适用项在取数时通过。`production_released` 始终为 false；报告不是实时监测，也不是生产放行。后续修改、重新连接、插话和重新检查使旧通过结果失效。

## 命名尺寸与标注公差

新增 `dimension_range` 和 `dimension_tolerance_range`。需求除文字 `expected` 外，还必须提供结构化 `measurement`：

- `name`：`dimension_list` 返回的精确名称，例如 `D1@Sketch1`，不得模糊匹配其他尺寸。
- `unit`：`mm`、`deg` 或 `count`；数量只接受非负整数区间，不支持公差包络。
- `minimum`、`maximum`：用户确认的有限数值闭区间，必须下限不大于上限。以结构化范围作为判定条件，确认卡和报告均完整展示。

例如允许范围是 19.9 至 20.1 mm：`dimension_range` 检查当前模型参数值是否在区间内；`dimension_tolerance_range` 则检查名义尺寸加下偏差、上偏差后得到的整个区间是否包含于允许范围内。后者仅支持明确读出的双向、对称及极限公差；无公差、读取失败、配合代号或单侧公差保持 UNKNOWN，不自行推算。

只在计划使用这些检查器时读取 `dimension_list`，最多取 1000 行。列表截断、遍历中断、旧执行器缺少 `complete`、名称缺失/重名、单位不符和非有限值均保持 UNKNOWN。取数仍受前后文档修改戳检查及原有执行中断规则保护。

这证明的是指定 CAD 参数和公差标注的状态，不证明它们对应最终实体上的目标距离，更不证明加工后的实物合格。最终几何测量、形位公差、公差链及实物检验仍需独立检查。

## 有界修复与停止

- 有 FAIL 时先修复确定缺陷，即使同时存在 UNKNOWN；修复后仍有 UNKNOWN 则停止等待核验。
- 最多 3 次自动修复，每次最多 6 个模型轮次、30 次修改操作；任务最多 8 次工程检查。
- 后一轮失败项集合必须严格减少，否则停止自动修复。这是保守的进展判断，不是连续几何误差优化器。
- 冻结后不允许在修复中修改阈值；只有用户插话后重新确认计划才能变更需求。
- 执行器断连、传输异常及未知执行结果沿用原有立即停止规则，保留检查点，不自动重放。
- 普通建模任务仍没有固定累计轮数/工具次数上限。上述预算只约束工程检查和缺陷修复。

## 验证与分发

专项测试使用合成 CAD 返回，覆盖确认、规则加载、约束冻结、证据缺失、报告失效、修复、停止和 API 锁释放。它们不替代真实 SolidWorks 和模型服务联动验收。

本轮七项边界修复验证：后端全量 866 项通过（其中工程专项 165 项），前端 37 个测试文件、216 项通过；Vue/TypeScript 生产构建通过。新增 39 项后端边界用例及 7 项来源组件交互用例，覆盖身份替换、确认等待中的身份变化、首次保存、工程图、只读预算和收尾断连/工具缺失/异常。此前 C# 执行器构建及 161 个工具目录校验通过，本次未修改执行器。测试使用合成 CAD 返回，没有执行真实 CAD 建模、调用外部模型服务或安装/卸载软件。

源码版本仍为 0.9.0。已制作的 0.9.0 安装包包含最初工程闭环与命名尺寸检查，但未包含之后的来源折叠和本次项目多文档修复；本次未重新打包或替换运行中的桌面应用。运行更新后的源码服务后新建续作任务可使用新接口；旧执行器证据字段不足时仍保守地报告 UNKNOWN。
